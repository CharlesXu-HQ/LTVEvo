# LTVEvo: Agent-led future customer value experiments

## Scope

This is a separate open-source project. It predicts a customer's observed value in a fixed future horizon and ranks customers by that value. It does not estimate treatment effects, optimal contact times, or coupon ROI. The first adapter uses every available row of UCI Online Retail II, excluding rows that cannot contribute to the specified purchase-value target. It does not sample transactions.

For Online Retail II, the first target is **future positive purchase amount before refunds**. A valid purchase line has a customer ID, positive quantity, positive unit price, and a non-cancellation invoice. Missing IDs, cancellations, nonpositive amounts, and out-of-range timestamps are counted in a data-quality report. This proxy must not be described as net revenue, margin, or lifetime causal value.

## Frozen task contract

`task.json` specifies the raw data path and SHA-256, column mapping, prediction horizon, monthly observation dates, train/validation/test observation date ranges, target definition, seed, primary metric, and evaluator version. For each observation date, features use transactions strictly before that date; the label uses valid purchases in `[as_of, as_of + horizon)`. A date is usable only if its full label window is observable. The latest training label window must end no later than the first validation observation date, and the latest validation label window must end no later than the first test observation date.

Each example is a known `(customer, as_of)` pair. The Agent never receives the test labels or test metrics during search. A dataset or task contract change creates a different experience identity. Historical user identifiers are used for grouping and paired uncertainty, never as model features.

## Candidate and evaluation contract

A candidate is a Python module with `fit_predict(train, validation, *, feature_columns, target_column, device, seed)`. It may engineer features and change PyTorch architecture/training, but cannot change the frozen task or access future labels. The runner validates output length and finite predictions, then evaluates on the fixed validation split. With `device=cuda`, the candidate must return a CUDA `torch.Tensor`; the runner checks this before converting predictions for scoring. This provides runtime evidence of GPU prediction, though it cannot prove every training operation used the GPU. Container execution has no network and read-only input mounts; GPU experiments fail rather than silently falling back to CPU.

Primary selection: lower validation MAE among all-zero, historical-spend, PyTorch seed, and Agent candidates. Secondary diagnostics: RMSE, normalized Gini, top-decile value capture, and decile calibration. The all-zero reference prevents false progress on zero-heavy labels. Candidate predictions on the same rows receive paired customer-cluster bootstrap intervals against the historical and all-zero references. The test split is evaluated only once for the selected champion.

## Agent loop

Every iteration reads completed experience for exactly this dataset and task, diagnoses current errors, states a falsifiable hypothesis, writes candidate model code, evaluates it, compares metrics to the hypothesis, and records a reflection. Normal iteration and reporting use provider reasoning effort `high`; suspicious leakage, anomalous metrics, or target/metric mismatch trigger `max` review. Provider URL, API key, and model name are configurable. An experiment journal contains the dataset/task fingerprint, candidate source hash, full metrics, hypothesis, reflection, and missing-feature requests for human dataset improvement.

## First release acceptance

1. Full Online Retail II import and leakage-safe snapshots, with provenance and exclusions reported.
2. A reproducible historical baseline and a PyTorch model evaluated with frozen metrics; full data, no demo subset.
3. Agent code iteration that resumes from a journal, keeps test labels sealed during search, and records hypothesis-to-result reflection.
4. Final paired confidence intervals and one-time test evaluation; truthful reporting of what the results do and do not establish.
5. English and Chinese README, Apache-2.0 license, minimal CLI, tests for split leakage and evaluation semantics.
